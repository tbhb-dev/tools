# GitHub polling

Agents get GitHub CI and pull request state from awrel, which relays webhook events into a session: subscribe with the repository and the event type, such as `check_run` conclusion events. That's the way to watch GitHub state. Polling GitHub instead burns the account's REST quota, which every agent shares. A hook stops the common polls, and a shim budgets what remains. The budget is a backstop, not the way to watch GitHub state.

- `guard-gh-poll` denies `gh run watch`, `gh run list` and its alias `gh run ls`, with a flag before the verb as in `gh run -R OWNER/REPO list` and with a quoted name such as `$'gh'`, `gh pr checks --watch`, `gh api` or `gh query` with `--paginate`, and reads of the list endpoints `actions/runs`, `actions/workflows/W/runs`, `actions/jobs`, `check-runs` and `check-suites`. It also denies a `while`, `until` or `for` loop that runs `gh`, or runs both `sleep` and `pgrep`, such as the self-matching wait `while pgrep -f fetch.py; do sleep 5; done`. Single-object reads pass, such as `actions/runs/ID`, `pulls/N`, `commits/SHA/check-runs`, `actions/runs?head_sha=SHA` for one full commit hash, and `rate_limit`. An empty `--method` resets to the default method: a GET without `-f` fields or `--input`, and a write with them. It scans `bash -c`, `eval`, `ssh HOST COMMAND` and a here-document fed to a shell. The one exception is a granted allowance for a measurement pass: `gh run list -R OWNER/REPO --limit 100 --json FIELDS`, with the exact fields and order of the measurement runner, once for each repository in a grant file under `~/.local/state/tbhb` and not after the grant's expiry date. Repository names match in any case, and the spellings share one allowance. A grant whose `repos` isn't a list of `OWNER/REPO` strings, or that holds an empty, `.`, `..` or Unicode name, grants nothing. A count file beside it records each repository once spent, under a file lock. The guard denies `xargs` or `parallel` around `gh run`, including after an option's value and inside an `env -S` string, because the listing words can come from input and each repeat is a separate call, and it spends the allowance for a listing that follows a redirect. Only the operator writes the grant and count files. The guard denies a Claude Code Write, Edit, MultiEdit or NotebookEdit to `gh-poll-allowance.json` and `gh-poll-allowance.count` in any case, with a suffix such as `.lock` or `.bak`, or through a symbolic or hard link under another name, and any shell command that names either in any case or after unquoting, such as `x."count"`. It also denies `rm`, `mv`, `cp`, `rsync`, `ditto` and `ln` on the state directory, a parent, or a glob or brace that can match one of them or the grant or count file, written as an absolute path, `~` or `$HOME`, in any case, with a brace list or a single-character or integer range such as `{t..t}` or `{b..z..2}` expanded, with `.`, `..` and `//` collapsed. It also denies `xargs` or `parallel` with such a mover and a state path anywhere in the command. The lock file beside the count file counts as a state file too. The mover check reads the attached `--target-directory=PATH` and `-tPATH` forms too. The guard leaves a range with a bound over nine digits alone, and it denies a path with more than 4096 spellings. It reads the first 256 candidates of a brace range, so a name past that isn't matched. Zero padding as in `{001..002}` isn't kept. A `HOME` that contains a space splits into two words when the guard flattens a quoted word, so a quoted absolute path under it isn't protected. The mover list stops at those six, so `unlink`, `truncate`, `shred`, `tee`, `dd of=`, `sed -i`, `find -delete` and `echo GLOB | xargs unlink` pass for a glob spelling. The name check catches a literal name. A state path anywhere in the command, in any pipeline stage, with `xargs` or `parallel` and one of the six movers draws a denial when each name is plain or wholly quoted, such as `echo GLOB | xargs rm -rf` and `"xargs" rm -rf PATH`. A name split by an empty quote or a backslash, such as `xa""rgs`, `r""m` or `x\args`, passes when the state path appears only in an earlier stage, and draws a denial when the path is an argument of the mover. `cat list | xargs rm -rf` passes because a state path appears nowhere in it. The mover names match in any case, so `RM -rf` on the state directory draws one too. The guard scans `env -S 'gh run list'`. Case variants of `gh`, a name built as `g$'h'`, and the attached `-t` form after other short options, such as `cp -vtPATH`, aren't read. The guard also denies `echo` of a state file's name. `tee` and wildcard writes to the state files, a computed path, a shell fed on stdin by a here-string, a pipe or `source`, `exec -a`, `eval --`, `env -S`, a `gh api` path with percent-encoded characters, shell options set with `bash -O`, a quoted program name after a wrapper such as `env $'gh'`, and a relative path after `cd`, `${HOME:-/x}`, `$XDG_STATE_HOME/tbhb`, `python3 -c` file writes, `shutil`, `tar -C`, `chmod -R`, `git -C clean`, variable indirection, and a program name taken from input aren't seen. The `apply_patch` and Antigravity edit tools don't reach the file check, so the guard doesn't cover an edit through them. A shell command that reaches a file through a link under another name isn't caught. It can't see inside a script file or a computed path. The allowance doesn't cap listings hard yet. A listing that starts with a redirect, such as `2>&1 gh run list`, spends nothing. A command the scanner can't parse, such as one containing `gh api 'http://['`, lets every listing in it through. The allowance and the state-directory rule stop accidents. Deliberate obfuscation gets past them. The guard spends its repository's call even if the shell doesn't run it. Only the poll denies name awrel. The denies for the grant and count files, a repeated listing and `unset`, and the shim's config and state-error refusals don't. The same hook denies `unset` and `env -u` of the 1Password service account token's variable. A command keeps the environment the harness gave it.
- `gh-shim` budgets the `gh` calls that scripts make, which no hook sees. In an agent session it refuses a call when the root session has made `[gh_budget] hourly_limit` `gh` calls in the past hour, or when the account has fewer than `core_floor` core REST requests left. It checks that with `gh api rate_limit` at most once a minute. A refusal goes to stderr and names awrel and the budget. Otherwise, and always outside an agent session, it runs the real `gh` unchanged. The state is under `$XDG_STATE_HOME/tbhbdev/gh-budget`.

Claude Code gets the shim on PATH from the SessionStart hook, which adds an `export PATH` line to `$CLAUDE_ENV_FILE`. Codex and Antigravity have no setting that prepends to PATH, so start them as `tbhbdev alpha agent-env codex` or `tbhbdev alpha agent-env agy`, followed by the harness's own arguments. A process tree that doesn't inherit that PATH, or a `gh` run by its absolute path, skips the shim. Neither mechanism is a security boundary.
